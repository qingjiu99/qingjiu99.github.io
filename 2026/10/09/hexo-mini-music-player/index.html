给博客加一个迷你音乐播放器

发表于2026-10-09|更新于2026-10-09|技术
|总字数:2205|阅读时长:9 分钟|浏览量:

一直想给博客角落放个音乐播放器：平时不占地方，想听点一下，歌单也能翻。参考了 Aciano 的《Hexo：为博客插入音乐》，用 APlayer + Meting 把网易云歌单接进来，又把默认那个方块样式改成了左下角的圆唱片。

长什么样

平常它只是左下角一枚唱片，暂停时中间显示播放键，播放时唱片缓慢旋转、把鼠标移开就只剩封面：

点唱片右侧的小箭头，展开成一张卡片，可以看歌名、拖进度、切歌；再点歌单图标就弹出完整歌单，当前播放的那首会高亮并自动滚到可见位置：

为什么是 APlayer + Meting

试过两条路，都不合适：

  • 网易云官方的外链播放器：样式写死改不动，而且有版权的歌直接不给生成外链，等于歌单选不了。
  • hexo-tag-aplayer 插件：它的思路是往主题里注入播放器，但 Butterfly 5.7 已经移除了 aplayerInject 配置项，用它反而要去改主题源码，升级主题时又会冲突。

最后选的是 APlayer（播放器本体）+ Meting 接口（把歌单 ID 换成音频直链），通过主题的 inject 注入，一行主题代码都不用改：

接入：5 行配置 + 2 个文件

1. 在 _config.butterfly.yml 里注入资源

APlayer 我没有走 CDN，而是把 aplayer@1.10.1/dist 下的 APlayer.min.css 和 APlayer.min.js 放进了 source/vendor/aplayer/。理由很实际：博客在国内访问，CDN 偶尔抽风就会整个播放器都不出现，本地化之后只有「歌单数据」还依赖网络。

inject 里的内容会原样插到 </head> 前和 </body> 前，所以 CSS 放 head、JS 放 bottom。注意 YAML 里这些字符串我用单引号包起来了，因为里面同时有 " 和 :。

2. 样式 source/css/music-player.css

核心就三件事：把唱片变圆、让它转、展开时变成卡片。

颜色不写死，用 var(--btn-bg) / var(--card-bg) 这些主题变量，这样深色模式会自动跟着变。

没有用 MetingJS，是因为它把「拉数据」和「建播放器」绑在一起，拿不到播放器实例；自己 fetch 只有十几行，但实例在手，后面想干什么都方便。

踩到的坑

这几个都是真机上试出来才发现的，记一下省得下次再踩：

1. 歌单面板高度不生效，200 首歌把面板撑到 6700px 高，打开还停在列表末尾。
APlayer 会把 listMaxHeight 原样写进 max-height，所以传数字 300 就得到 max-height: 300——没有单位，浏览器直接丢掉这条声明。传字符串 '320px' 才对。为了双保险，CSS 里也给滚动容器定了一次高：

给 ol 而不是给外层容器定高，是因为折叠靠的是外层 .aplayer-list-hide { max-height: 0 !important }，写在外层会互相打架。

2. 暂停按钮会跟着唱片绕圈。
APlayer 默认把「暂停」按钮放在封面右下角（播放按钮才在正中间），封面一旋转，它就会绕着圆心跑。把两个按钮都居中就好了：

3. 不要自己挪那排「上一首 / 播放 / 下一首 / 歌单」图标。
我一开始嫌它们贴着右边缘，整排往左平移了 30px，结果撞到了歌名。后来才看清：这些图标是相对 .aplayer-controller 定位的，而 APlayer 已经在播放器主体右侧留了 18px 给收起箭头、并给歌名留了 105px 的宽度，三者本来就是错开的。动图标之前先算清楚它相对谁定位。

4. 歌单里会有歌曲 404。
比如我歌单第一首在网易云已经下架，Meting 接口返回 404，浏览器播放报错。APlayer 自己会等 2 秒跳到下一首，属于正常容错，不用管。

5. 自动播放基本不可能。
浏览器的自动播放策略要求至少有一次用户交互，autoplay: true 只会换来一堆 NotAllowedError。所以我关了自动播放，并且用 sessionStorage 记住「在放哪首、放到第几秒」，翻页回来接着放——但恢复出来是暂停状态，点一下才出声。

6. 播放器的 DOM 要挂在 body 下面。
position: fixed 遇到有 transform 的祖先会失效（变成相对那个祖先定位）。所以我是让脚本自己 document.body.appendChild() 一个容器，而不是把它写进页面的某个区块里。

顺手加的几样

播放器装上之后又补了几个「安知鱼味」的东西。

**音乐馆页面 /music/**：同一份歌单配置，换成一个非吸底的大播放器——封面、歌词、完整歌单都在，适合专门坐下来听。为了让两边共用一份配置，我把迷你播放器脚本里的歌单配置和取数据逻辑挂到了 window.miniMusic 上，页面脚本直接调：

右下角「随机前往一篇文章」：文章列表不用额外的接口——本地搜索用的 search.xml 里本来就有全部文章链接，取一次存进 sessionStorage，之后点按钮就是随机跳一个。按钮直接插进主题的 #rightside，尺寸、悬停变色、深色模式全都跟着主题走，一行 CSS 都不用写。

导航分组：顺便把导航改成了下拉分组。Butterfly 原生支持——menu 里某个键的值写成对象，就是一个下拉菜单：

改成你自己的

想改什么 改哪里
换歌单 source/js/music-player.js 顶部 CONFIG.id
换配色 _config.butterfly.yml 里的 --heo-main
换平台 CONFIG.server 改成 tencent、kugou 等，type 也可以换成 song / album
唱片大小 / 离边距离 CSS 开头的 --mini-music-disc、--mini-music-gap

另外，在浏览器控制台里直接 miniMusicPlayer.play() 就能控制它，调样式的时候挺方便。

小结

整件事其实很简单：APlayer 负责好看，Meting 负责把歌单 ID 变成能播的地址，inject 负责让它出现在每个页面。麻烦的从来不是「接进来」，而是把它调成不挡视线、不打架、翻页不闹脾气——上面那 6 个坑基本都花在这上面了。

现在它安安静静待在左下角，想听就转起来。
