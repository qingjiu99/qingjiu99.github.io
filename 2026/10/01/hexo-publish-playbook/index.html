三个前置条件

发布能不能成功，取决于这三样。出问题先查这里，再查命令。

1. Node.js 可用

报错就是没装，或者没进 PATH。

如果用的是 Cherry Studio 自带的 Node，位置在 %APPDATA%\CherryStudio\Toolchain\mise\shims，每次开新终端都要重新 set 一次（上面命令块的第 1 行）。想省掉这步，去 nodejs.org 装个 LTS 版，装完重启终端即可。

2. 代理已启动

GitHub 直连不通，必须先开代理软件。

关键：光开着代理软件不一定够。git 底层用 libcurl，不一定读取系统代理设置，所以要用第 2、3 行显式指定端口。端口号填你代理软件的实际端口（Clash 常见 7890 / 7897）。

验证代理是否通：

能返回内容就正常。不加 -x 参数测一次，如果直连不通、走代理通，就说明环境没问题。

3. 仓库配置正确

_config.yml 里：

仓库名必须是 <用户名>.github.io 这种格式，这是 GitHub Pages 的命名规则。

完整发布流程

写文章

文件生成在 source\_posts\ 下。写完记得填 front-matter：

<!-- more --> 是摘要分隔符，不写的话首页会把全文铺出来。

文件名会变成网址的一部分，建议用英文或拼音，中文标题写在 title 里就好。

本地预览

打开 http://localhost:4000 看排版，确认后 Ctrl+C 停掉。这一步不需要代理，可以先在没网的情况下写完排版。

部署

generate 成功会显示 N files generated。如果这一步就报错，说明是文章内容或配置的问题，和网络无关。

故障排查表

这张表是我实际踩过的坑，按”现象 → 原因 → 解决”排列：

现象 原因 解决
'npx' 不是内部或外部命令 Node 不在 PATH 命令块第 1 行不能漏
Failed to connect to github.com port 443 代理没开，或 git 没走代理 开代理 + 保留 HTTP_PROXY / HTTPS_PROXY 两行
弹出 Connect to GitHub 授权窗口 首次在新机器 / 新环境发布时出现，凭据会缓存，之后通常不再弹 保持「Browser/Device」页，点 「Sign in with your browser」
登录窗口关不掉，但命令行已显示 Deploy done GCM 的残留窗口，此时已无进程在等待它 直接点 ✕ 关掉，不要再点授权按钮
网站显示的是旧内容 / 别人的内容，新文章 404 Pages 还在重建，看到的是上一次部署的旧站 等 1～2 分钟再刷新，别急着重配
网站一直是 404 仓库默认分支不是 main 仓库 Settings → Branches → 默认分支改为 main
内容确认已构建完成，但打开还是旧的 浏览器缓存 Ctrl+F5 强制刷新
Repository not found 仓库名或账号不对 检查 _config.yml 里的 deploy.repo

排查顺序建议：先看命令行输出到哪一步失败了，再对号入座查表。命令行有 Deploy done 但网站不对 → 问题在 Pages 构建或缓存；命令行就报错了 → 问题在环境或配置。

命令速查

命令 作用 需要代理？
npx hexo new "标题" 新建文章 否
npx hexo generate（g） 本地生成 否
npx hexo server（s） 本地预览 localhost:4000 否
npx hexo clean 清理缓存 否
npx hexo deploy（d） 部署到远端 是

只有最后一步需要代理，写文章和预览都是纯本地的。

把这块命令存成记事本放在手边，每次发布复制粘贴就行。发布这件事本身不难，难的是出错时知道问题出在哪一环——希望这张排查表能帮你省点时间。
