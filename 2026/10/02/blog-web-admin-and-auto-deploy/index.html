给博客装上网页后台和自动发布

发表于2026-10-02|更新于2026-10-09|技术
|总字数:2134|阅读时长:9 分钟|浏览量:

博客上线之后，很快发现两个别扭的地方：只能在电脑上写，而且每次发布都要手动敲命令。这篇记录我怎么把这两个问题解决掉，顺便加上访问统计。

问题在哪

静态博客有个天然的短板：没有后台。

WordPress 那种动态博客，打开 /wp-admin 就能写文章、传图片、改设置。而 Hexo 生成的是纯静态网页，服务器上只有 HTML 文件，没有数据库、没有登录界面、没有任何管理入口。

所以之前写一篇文章的流程是这样的：

在家用电脑还行，出门在外想随手记点东西就完全没办法。

目标：手机上能写 + 提交后自动发布。

整体方案

拆成三件事：

要解决的问题 方案
没有编辑界面 Pages CMS（网页版 Markdown 编辑器）
每次要手动发布 GitHub Actions（提交后自动构建发布）
不知道有没有人看 不蒜子（访问统计）

这三件事里，第二件是基础 —— 因为网页后台改的是源码仓库里的 .md 文件，改完还需要重新生成才能上线。光有编辑器没有自动发布，在网页上写完还得回电脑敲命令，等于白装。

一、网页后台：为什么选 Pages CMS

先说结论：没用 Decap CMS。

Decap CMS（原 Netlify CMS）是最有名的静态博客后台，但它有个绕不开的麻烦 —— 它的登录授权需要一个服务端。GitHub Pages 是纯静态托管，跑不了服务端，所以你得额外准备一个 OAuth 代理（Cloudflare Workers 之类），配置量一下就上去了。

后来找到了 Pages CMS，它的思路完全不同：

内容直接存在你的 GitHub 仓库里，没有数据库、没有 API、没有额外后端。

官方提供托管版，用 GitHub 账号登录就能用，不用自己部署任何东西。而且是开源的（MIT 协议）、免费、原生支持手机。

一个需要权衡的地方

安装 Pages CMS 时，它会请求挺宽的权限：读写代码、Actions、Workflows、Administration。

  • 读写代码是必需的 —— 编辑文章就是改文件，没这个它干不了活
  • 其余的（Actions / Workflows / Administration）是为了支持”在后台一键触发工作流”之类的功能，超出了最低需要

GitHub 的授权页是”要么全给、要么不装”，没有细粒度勾选。所以建议：**在授权时把仓库范围限制成”只选这一个仓库”**（默认是全选），别把其他项目的权限也一起交出去。

为什么要单独配一个令牌

工作流在源码仓库里运行，但要往网站仓库推送 —— 这是跨仓库操作，GitHub 默认的 GITHUB_TOKEN 权限不够。

所以要创建一个细粒度访问令牌（PAT），并且把权限压到最小：

配置项 值
仓库范围 只选网站仓库，不选”所有仓库”
权限 只需要 Contents: Read and write
其他权限 一个都不要给

创建后存进仓库的 Settings → Secrets and variables → Actions，名字叫 DEPLOY_TOKEN。

为什么要压到最小：这个令牌存在仓库里，虽然 GitHub 会加密，但权限越小，万一泄露的影响面就越小。它只负责推网页文件，给它访问其他仓库或者管理权限都是多余的。

踩过的坑

文件名会变成网址

Pages CMS 新建文章时，默认用标题生成文件名。标题写中文，文件名就是中文，网址会变成这样：

能用，但分享出去很难看，也不利于记忆。

建议在新建时手动把文件名改成英文或拼音，标题照旧写中文。我在配置里专门打开了文件名输入框，就是为了这个。

工作流第一次跑会失败

令牌还没配好的时候，工作流一跑就会在最后一步失败。这是预期内的 —— 它需要那个令牌才能往网站仓库推送。

失败信息里会直接告诉你去哪里配置。配好之后在 Actions 页面点 Re-run all jobs 就行。

权限不广播

这个跟博客无关，但顺带记一下：Windows 上改完环境变量（PATH），已经打开的程序不会自动更新，它们还拿着启动那一刻的旧环境。

所以改完 PATH 后要关掉所有相关的终端窗口重新开，或者直接重启电脑。

小结

改造完之后回头看，最值得的一条经验是：自动发布是基础，其他两个都建立在它之上。

没有自动发布，网页后台只是个”远程改文件的工具”，改完还得回电脑发布，意义不大。有了它，写作才真正脱离了对某台电脑的依赖。

另外，选工具的时候**优先看”要不要额外维护服务”**。Decap CMS 功能更全，但要自己搭 OAuth 代理；Pages CMS 简单，因为它把复杂度放在了”用 GitHub 仓库当数据库”这个设计上。对个人博客来说，少一个要维护的东西，比多几个功能重要得多。
