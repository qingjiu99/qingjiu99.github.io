Markdown 常用语法速查（附我踩过的坑）

2026年10月02日 · 技术 · #Markdown #写作 · 阅读 --

写博客这些天，把常用的 Markdown 语法整理了一遍。这份速查表既是给自己以后翻，也给同样刚开始写的朋友省点事——顺带把我自己踩过的坑都记下来。

为什么写这个

Markdown 的设计理念是「用最少的符号，表达最基本的排版」。它没有复杂的菜单和按钮，所有格式都靠几个符号敲出来。

好处是上手极快，坏处是有些符号长得像、容易记混——比如链接和图片只差一个感叹号。所以下面按用途分类整理，需要哪条查哪条。

一、标题

用 # 表示层级，几个 # 就是几级标题：

渲染效果就是本文这样，## 会带一条下划线分隔。

⚠️ # 后面必须有一个空格。写成 #标题 是不生效的，会原样显示出来。

二、强调

效果 写法
加粗 **加粗**
斜体 *斜体*
加粗斜体 ***加粗斜体***
删除线 ~~删除线~~
行内代码 用一对反引号 ` 包起来

行内代码很适合写命令名、文件名、字段名，比如 _config.yml、npx hexo d。

三、链接与图片

这两个长得几乎一样，图片只多一个感叹号：

  • 链接：方括号里是点击时看到的文字
  • 图片：方括号里是「替代文字」。图片加载不出来时会显示它，鼠标悬停时也会显示。圆括号里只能放图片网址。

这是最容易写错的一条，我在下面「踩过的坑」里专门说了。

四、列表

列表项之间不空行，会渲染成紧凑的一坨；空一行就会变松散，行距更大。写文章按需选择。

五、引用

用 > 开头，适合放提示、补充说明：

效果就是这样，左边会有一条竖线。

六、代码

行内代码用一对反引号包起来，比如 _config.yml、npx hexo d。

整段代码用三个反引号包住开头和结尾，并可以在开头的反引号后面标注语言，让关键词有高亮：

开头那个 js 就是语言标记，换成 bash、cmd、yaml、markdown、text 都可以。不标也能用，只是没有语法高亮。

代码块渲染出来是带行号的，效果可以看这里。

七、表格

第二行的 | --- | --- | 是必须的，它告诉解析器这是表格而不是普通文字。

💡 表格列数多的时候，与其在源码里对齐空格，不如随便写、让它自己渲染——源码对齐纯属自我感动，渲染出来都一样。

八、分割线

单独一行写三个减号：

渲染出来是一条横线。

⚠️ 小心：文章开头如果出现 ---，它表示的是 front-matter 的开始，不是分割线。所以正文里用分割线时，别放在第一行。

九、Hexo 专属的两个标记

上面是通用 Markdown，下面这两条是 Hexo 特有的，只有写博客才用得到。

1. front-matter（文件开头那段）

每篇文章必须以它开头，否则 Hexo 根本不认这篇文章：

字段 说明
title 文章标题
date 决定排序，首页按时间倒序
tags 标签，方括号包裹，多个用逗号隔开
categories 分类，写法同上

用 npx hexo new "标题" 建文件的话，这段骨架会自动生成好。

2. 摘要分隔符

在摘要和正文之间，单独加一行 HTML 注释，内容是 more 这个词：

这行上面的内容会显示在首页列表里当摘要，下面的内容要点「阅读全文」才看得到。

不写也能用，只是首页会把整篇全文铺出来，列表会变得很长。

十、我实际踩过的三个坑

这部分是重点，都是我真实踩到、而且不报错的坑——最难受的就是这种。

坑二：文章「消失」

我在 source\_posts\ 下新建了一个 .md，写得好好的，发布也显示成功，但文章就是不在网站上。

原因：文件开头漏了 front-matter。Hexo 遇到没有 front-matter 的文件会直接跳过——不报错、不提示，静默忽略。

所以遇到「发布成功但文章找不到」，第一件事就是检查文件头两行是不是 ---。

坑三：段落之间必须空行

Markdown 里一个换行不算换行。想让两段分开，中间必须空一行：

这个坑很隐蔽，因为源码里看起来是分成两行的，但渲染出来变成了一坨。

结语

Markdown 的语法一共就这么点东西，写个三五篇文章就熟练了。

真正常用的其实只有四五个：标题、加粗、链接、图片、代码块。其余的记不住也没关系——需要的时候翻一下就行，比如现在这篇。
