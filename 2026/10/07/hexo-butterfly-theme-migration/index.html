我的 Hexo 博客换上 Butterfly 主题

发表于2026-10-07|更新于2026-10-09|技术
|总字数:936|阅读时长:4 分钟|浏览量:

这次给个人博客换了一个更有表现力的主题：Butterfly。相比之前的自研 Aurora 主题，Butterfly 提供了更完整的卡片式首页、侧栏组件、深色模式、目录、搜索和文章阅读体验。

为什么选择 Butterfly

个人博客不只是文章的容器，首页、导航、归档和文章详情页也会影响阅读体验。Butterfly 的视觉设计比较丰富，同时保留了 Hexo 静态生成的优点：构建简单、访问速度快、部署成本低。

这次迁移主要看中了几个功能：

  • 卡片式首页和侧栏信息卡片。
  • 文章目录、阅读进度和代码块工具栏。
  • 内置深色模式和移动端适配。
  • 分类、标签、归档等页面的统一设计。
  • 本地搜索和文章字数、阅读时间统计。

这次改了什么

博客仍然使用 Hexo 7.3，文章源文件和永久链接都没有改变，只替换了主题层：

项目中新增了 themes/butterfly 主题目录，并安装了 hexo-renderer-pug 与 hexo-renderer-stylus。Butterfly 的站点配置单独放在根目录的 _config.butterfly.yml，这样以后升级主题时，个人配置不会和主题默认配置混在一起。

首页与导航

现在首页采用 Butterfly 的文章卡片布局，文章摘要会根据正文自动生成。导航栏增加了：首页、归档、分类、标签和关于页面；侧栏则展示作者介绍、最近文章、分类、标签和归档。

如何本地预览

然后打开 http://localhost:4000。如果只想检查构建是否成功，执行 npx hexo generate 即可。

部署方式没有改变

博客仍然通过 GitHub Actions 自动部署：推送源码到 main 分支后，工作流会安装依赖、执行 Hexo 构建，再把 public 目录发布到 GitHub Pages 仓库。

主题切换并不需要改变域名或部署平台，这也是静态博客的一大好处：内容、主题和托管平台之间相对独立。

迁移时需要注意什么

主题切换并不只是修改一个 theme 字段，还需要确保构建环境拥有主题和对应渲染器。尤其是自动部署时，主题目录必须进入源码仓库，否则本地可以生成，GitHub Actions 却会因为找不到主题而失败。

另外，Butterfly 的默认配置功能很多，不建议一开始全部打开。更稳妥的做法是先启用导航、目录、深色模式、搜索和统计等常用功能，再根据访问情况逐步调整。

小结

这次迁移保留了原有文章和 URL，只更换了展示层。Butterfly 让博客首页和文章页更完整，也为后续增加评论、友链、搜索和更多互动功能留下了空间。

对个人 Hexo 博客来说，主题不需要追求最复杂，关键是让内容更容易被发现、更舒服地阅读。接下来会继续根据实际使用体验，调整配色、封面和侧栏内容。
